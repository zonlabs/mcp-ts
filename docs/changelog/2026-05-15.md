## New features

### Neon storage backend

A new [Neon storage backend](/storage-backends/neon) lets you persist MCP sessions and connections in a serverless Postgres database. Configure a secure Neon connection string, and optionally enable Row-Level Security and `pg_cron` cleanup jobs to expire stale sessions automatically. See the [storage backends overview](/storage-backends/overview) for a comparison with the other supported stores.

### Tool approvals and annotations

The [tool router](/core-concepts/tool-router) now supports an approval step before a tool is executed, plus richer annotations that travel with each tool definition. You can require human confirmation for sensitive tools and surface extra metadata to the model and UI without changing your tool schemas.

### Deeper tool search

The tool index now walks into nested schema metadata when matching a user query, including arguments inside object and array properties. Search across large tool catalogs returns more relevant matches without any configuration change.

## Updates

### Standardized API naming

We unified naming across the client, server, and storage APIs so the same concept has the same name everywhere:

- Identity parameters are now `userId` everywhere (client, server, storage). See the updated [client](/reference/client) and [server](/reference/server) references.
- Session data methods on storage backends use a consistent verb form. See the [storage reference](/reference/storage).
- The HTTP transport name is now `streamable-http` across configuration and runtime.

If you previously passed `identity` or used the older method or transport names, update your call sites to the new ones.

### Simpler client and handler setup

`SSEClient` and the Next.js MCP handler now build their URL and headers through a single, shared path. Header names and values are trimmed and empty entries are dropped, which makes it harder to ship a connection with a malformed header.

### Optional schema conversion dependency

`json-schema-to-zod` moved to an optional peer dependency. Apps that don't convert JSON Schema to Zod at runtime no longer pull it in, keeping installs leaner. Install it yourself if you rely on that conversion.

### Slimmer tool definitions

Tool definitions and summaries no longer carry runtime token cost estimates or the older inline annotations field. Token estimation has been removed in favor of approval flows and explicit annotations on the new tool definition shape.
