## Updates

### Clearer execution instructions for discovered tools

The [`mcp_get_tool_schema`](/core-concepts/meta-tools) meta-tool now returns explicit `executionInstructions` alongside the tool schema, telling the LLM to call `mcp_execute_tool` with the discovered tool name and `serverId` rather than attempting to invoke the tool directly. The tool's own description has also been updated to reinforce the same flow. This reduces a common class of failures where LLMs would skip the indirection step and call a discovered tool that wasn't actually registered as a runtime tool.

## Bug fixes

### AG-UI middleware stream stalls

Fixed an issue in the [AG-UI adapter](/ai-adapters/agui) where streamed responses could stall mid-flight, leaving the UI hanging or surfacing `INCOMPLETE_STREAM` errors after a tool call. The middleware now:

- Tracks continuation runs explicitly so the outer stream stays open until the follow-up turn finishes, instead of completing prematurely after the first run.
- Captures content from both streaming chunk events and full content events, so assistant text reconstructed for tool-call continuations is no longer truncated.
- Uses the correct camelCase field names when re-injecting assistant and tool messages into the conversation, so strict LLM providers no longer reject the continuation request.
- Cleans up inner subscriptions deterministically, preventing leaked subscribers when a run errors or is cancelled.

### LangGraph continuation loops

Resolved an issue where remote LangGraph agents could re-execute tool calls on every continuation, producing infinite loops or duplicated side effects. Tool calls that were already completed in a snapshot are now tracked and skipped on the follow-up turn, and snapshot-only continuation answers are passed through without triggering another agent run.

### AG-UI message identity

Stabilized message and tool-call identifiers across AG-UI continuation runs so that streaming UIs (CopilotKit and similar) no longer duplicate or re-render assistant turns after a tool result is appended.

### Duplicated streamed tool arguments

Fixed a crash on continuation when streamed tool-call argument deltas were concatenated as raw strings, producing invalid JSON like `{"a":1}{"a":1}`. The middleware now normalizes tool-call arguments in the assistant history so LangGraph and other strict consumers always receive valid JSON.

### Next.js chat example import

Corrected the relative import path for the agent in the Next.js [chat route example](/nextjs), so the app builds cleanly out of the box.
