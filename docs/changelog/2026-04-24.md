A packed week. Here's what's new across the three releases that shipped — v1.5.0, v1.5.1, and v1.5.2.

## New features

### Tool Router

Manage large tool catalogs without blowing up your LLM's context window. The new [Tool Router](/core-concepts/tool-router) offers three strategies: `all`, `search` (scales to 1,000+ tools via [Meta-Tools](/core-concepts/meta-tools)), and `groups` for application-specific tool sets.

### MCP Gateway

Expose local MCP servers to cloud AI clients like ChatGPT and Claude. The [MCP Gateway](/gateway/overview) opens a secure tunnel — no open ports, no firewall changes. Configure everything through a single [`mcp.json`](/gateway/configuration).

### AI framework adapters

Drop MCP tools into your existing AI stack with four new [adapters](/ai-adapters/overview):

- [**AI SDK**](/ai-adapters/ai-sdk) for Vercel AI SDK
- [**LangChain**](/ai-adapters/langchain) for chains and agents
- [**Mastra**](/ai-adapters/mastra) for the Mastra agent framework
- [**AG-UI**](/ai-adapters/agui) for remote agents over the AG-UI protocol

### Supabase storage backend

[Supabase](/storage-backends/supabase) is now production-ready as a storage backend, with PostgreSQL persistence, row-level security, AES-256-GCM encryption for sensitive fields, and built-in `pg_cron`-powered session cleanup.

### LocalStorage backend

Persist sessions in the browser with the new [LocalStorage backend](/storage-backends/overview) — ideal for client-side apps and prototyping with no server-side database.

### MCP Documentation Server

The docs are now a hosted [MCP server](/modelcontextprotocol). Add it to Claude Desktop, Cursor, or VS Code to give your assistant direct access to the full, always-current docs.

### OAuth popup helpers

The [React client](/react) now ships drop-in helpers for popup-based OAuth: `createOAuthPopupRedirectHandler()`, `useMcpOAuthPopup()`, and `McpOAuthCallbackContent`. The `postMessage` handshake between popup and opener is handled automatically. Plain redirect callbacks work too via `finishAuth(sessionId, code)`.

### Automatic reconnection

React and Vue hooks now recover from dropped connections on their own — no page reload required. Useful for long-running agents and apps on flaky networks.

### Tool search enhancements

The [`mcp_search_tool_bm25`](/core-concepts/meta-tools) meta-tool got smarter:

- **Direct selection** — Use `select:<name>` to fetch a tool description instantly, skipping the search index entirely.
- **Required terms** — Prefix a term with `+` (e.g. `+slack send`) to scope results to a specific integration.
- **Smarter scoring** — Matches on `serverName` and `name` now boost ranking, so integration-specific queries surface the right tools.

### MCP App Host integration

MCP Apps now render in sandboxed iframes via a full [App Host](/mcp-apps) integration with CSP-configurable sandbox proxy, resource preloading, fullscreen mode, host↔guest state sync, and a custom `loader` prop.

## Updates

### Project rebrand to MCP Toolkit

The project is now **MCP Toolkit** — a name that better reflects its scope across server, client, gateway, and adapters.

### New documentation site

All docs moved to a [Mintlify-powered site](https://docs.mcp-assistant.in) with refreshed navigation, search, and layout. Storage backends and AI adapters now each have dedicated sections.

### Automated session lifecycle management

The [Supabase backend](/storage-backends/supabase) cleans up stale sessions on a schedule: a 5-minute transient sweep for failed or abandoned flows, and a daily eviction for sessions untouched for 30+ days. Active sessions are never affected.

### Session rehydration on reconnect

When an SSE connection resumes, the server now restores the original session metadata (transport type, server URL, callback URL) so the client picks up exactly where it left off.

### Smoother connection state transitions

React and Vue hooks suppress intermediate states like `INITIALIZING` when a connection is already established, eliminating UI flicker during reconnects.

### Simplified MCP App rendering

Import `McpAppRenderer` and `getMcpAppMetadata` directly from the [React client](/react) for full control over when and where MCP App UIs render. The `useMcpApps` hook still works but is deprecated.

### Isomorphic storage architecture

Pass a `storage` option to the MCP client or multi-session client to swap between server-side (Redis, Supabase) and client-side (LocalStorage) backends without changing application code.

### Adapter namespace support

Tool adapters now support a custom prefix per adapter to prevent name collisions across multiple MCP servers.

### Gemini CLI compatibility

The server correctly handles Gemini CLI's `streamable-http` transport checks and MCP ping requests, so MCP Toolkit works with Google's Gemini CLI out of the box.

### Next.js example refresh

The [Next.js guide](/nextjs) includes a full-stack example with App Router, a chat UI, and inline MCP App rendering after tool calls.

## Bug fixes

- **OAuth reliability** — Improved callback handling and credential storage in the `useMcp` hook.
- **Duplicate auth events** — `AUTHENTICATED` is no longer emitted multiple times during transport fallback.
- **MCP Apps stability** — Fixed iframe white-screen flashes on load and stabilized client identity handling.
- **Tool name length** — Generated tool names no longer exceed protocol limits.
- **Event routing** — Shared event routing correctly reflects connection state updates in the UI.
- **Storage proxy deadlock** — Fixed a deadlock that could hang backend initialization.
- **Tool search `topK`** — Exact-match results now respect the requested result count.
- **Required-term embeddings** — Query text is normalized so semantic ranking stays consistent with BM25.
- **Select mode errors** — Not-found tools in `select:<name>` calls now surface to the caller with the originating `serverId`, and `isError=true` is set when every tool fails to resolve.
