## New features

### Direct tool selection in search

The [`mcp_search_tool_bm25`](/core-concepts/meta-tools) meta-tool now supports a `select:<name>` syntax that bypasses the BM25 index entirely. When the model already knows which tool it wants, it can skip discovery and fetch the exact tool description in one step — saving tokens and round trips.

*Example*: `select:github_create_issue` returns that tool directly.

### Required terms in search queries

You can now prefix any word with `+` to strictly require it in search results. This helps the model zero in on tools for a specific integration when generic terms would otherwise surface unrelated matches.

*Example*: `+slack send` only returns tools from the Slack server, even if other tools mention "send" more frequently.

See the [Meta-Tools guide](/core-concepts/meta-tools) for the full query syntax.

## Updates

### Smarter BM25 scoring

The [Tool Router](/core-concepts/tool-router)'s search index now applies heuristic bonuses when a query term matches an MCP server name or tool name. Tools tied to a specific integration (for example, "neon" or "apify") consistently rank above unrelated tools that only mention the term in their parameter descriptions.

### serverId-based tool routing

Tool routing now identifies servers by a stable `serverId` instead of `serverName`, improving reliability when multiple servers share similar names or when server names change.

## Bug fixes

- **Select-mode error surfacing** — Fixed an issue where tools that failed to resolve in `select:` mode were silently dropped. The response now captures and surfaces not-found tools and returns `isError: true` when every requested tool fails to resolve.
- **Required-term embedding queries** — Fixed required-term (`+term`) query text normalization so semantic embedding blends enforce required terms consistently alongside BM25.
- **Top-K for exact name matches** — The tool index now respects the `topK` limit when a query matches a tool name exactly, preventing oversized result sets.
