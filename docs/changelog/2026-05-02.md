## New features

### Server-scoped tool search

The primary discovery meta-tool (now [`mcp_search_tools`](/core-concepts/meta-tools)) accepts new `serverId` and `serverName` fields to restrict results to a single connected MCP server. Use `serverId` for an exact match, or `serverName` as a case-insensitive fragment (for example, `serverName: "database"` matches a server named `Database MCP`). This avoids cross-server collisions when multiple servers expose similarly named tools.

### Deterministic server listing

`mcp_search_tools` now supports an `operation: "list"` mode. When the user asks for every tool from a specific server, listing returns a paginated result with `totalCount`, `returnedCount`, and `nextCursor` metadata — no ranking, no surprises. Pair it with `serverId` or `serverName` to enumerate exactly one server's catalog.

The underlying [`ToolRouter`](/reference/tool-router) and `ToolIndex` expose matching `listServers()` and `listTools()` methods for direct use.

### `mcp_list_servers` meta-tool

A new diagnostic meta-tool lets the LLM inspect which MCP servers are currently connected, along with their IDs and tool counts. Use it as a fallback when [`mcp_search_tools`](/core-concepts/meta-tools) returns no matches — discover what's connected, then retry the search with a specific `serverId` or `serverName`.

## Updates

### Renamed primary search tool

The BM25 search meta-tool has been renamed from `mcp_search_tool_bm25` to [`mcp_search_tools`](/core-concepts/meta-tools) to reflect that it now handles both ranked search and deterministic listing through a single `operation` field. The previous name has been retired; update agent prompts and integrations to the new name.

## Bug fixes

- **Server name fragment matching** — Fixed inconsistent results when scoping discovery by `serverName`. Fragment matching is now case-insensitive and consistent across search, listing, and `select:` lookups.
- **Exact tool namespace matching** — Fixed an issue where exact tool names that overlapped with another tool's prefix could resolve to the wrong tool. `mcp_get_tool_schema` and `mcp_execute_tool` now respect exact namespace matches before falling back to fuzzy resolution.
