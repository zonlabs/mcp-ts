This week's releases (v1.5.0 and v1.5.1) focused on connection resilience, session management, and a better OAuth experience for React and Vue applications.

## New features

### OAuth popup helpers

The [React client](/react) now includes built-in popup helpers for OAuth flows. Use `createOAuthPopupRedirectHandler()` for one-line popup redirects, `useMcpOAuthPopup()` for opener-side coordination, and `McpOAuthCallbackContent` for a drop-in callback page. These handle the `postMessage` handshake automatically — or skip popups entirely with `finishAuth()`. See the [React guide](/react) and [Next.js guide](/nextjs) for examples.

### Automatic reconnection

The React and Vue hooks now support built-in reconnection. When a connection drops, the client can automatically disconnect and re-establish the session without a full page reload — ideal for long-running applications and agents recovering from transient network issues.

### Automated session lifecycle management

The [Supabase storage backend](/storage-backends/supabase) now includes automatic session cleanup via PostgreSQL's `pg_cron` extension:

- **Short-term purge** (every 5 minutes) — Removes failed or incomplete sessions whose TTL has expired.
- **Long-term eviction** (daily) — Cleans up active sessions untouched for 30+ days.

Active sessions with ongoing usage are never affected. Cleanup migrations are included when you run `npx mcp-ts supabase-init`. See the [Supabase storage guide](/storage-backends/supabase) for details.

## Updates

### Session rehydration on reconnect

When an SSE connection resumes after a disconnect, the server now rehydrates the original session metadata — including transport type, server URL, and callback URL — so the reconnected client picks up exactly where it left off.

### Smoother connection state transitions

The React and Vue hooks now normalize connection states in the UI. Intermediate states like `INITIALIZING` are suppressed for already-established connections, preventing flickering during reconnection or transport negotiation.

### Proactive session cleanup on failures

When a connection or authentication error occurs during setup, the session record is cleaned up immediately rather than waiting for the next scheduled sweep.

## Bug fixes

- **Duplicate auth events** — Fixed an issue where the `AUTHENTICATED` state could fire multiple times during transport fallback, causing redundant UI updates.
