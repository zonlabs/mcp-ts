## New features

### Direct tool selection with `select:` syntax

The [`mcp_search_tool_bm25`](/core-concepts/meta-tools#mcp_search_tool_bm25) meta-tool now supports a `select:<tool_name>` query prefix. When your agent already knows the exact tool it wants, it can skip the BM25 index entirely and retrieve the tool description in one call.

Example: `select:github_create_issue` returns the exact tool instantly, with no ranking overhead.

### Required terms with `+term` syntax

Search queries now support strict required terms. Prefix any word with `+` to force the index to only return tools whose name or description contains that word.

Example: `+slack send` guarantees only Slack tools are returned, even if unrelated tools use the word "send" more frequently.

## Updates

### Smarter ranking for integration-specific queries

The tool search index now applies stronger scoring heuristics when a query term matches an MCP server name or tool name. Queries like `neon` or `apify` now reliably surface tools from those integrations above unrelated tools that only mention the term in their parameters.

### More reliable tool routing

Tool routing across the [AI SDK](/ai-adapters/ai-sdk), [LangChain](/ai-adapters/langchain), and [AG-UI](/ai-adapters/agui) adapters now identifies servers by a stable `serverId` rather than display names. This prevents routing mix-ups when multiple servers share similar names.

## Bug fixes

- **`topK` now respected for exact matches** — Fixed an issue where exact tool name matches could bypass the configured result limit in `mcp_search_tool_bm25`.
- **Not-found tools surfaced in select mode** — When `select:<name>` is used for a tool that doesn't exist, the meta-tool now returns a clear not-found response including the `serverId` instead of failing silently.
- **Embedding queries normalized for required terms** — Required-term syntax (`+word`) now produces consistent results when semantic search is enabled alongside BM25.
