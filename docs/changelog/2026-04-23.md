## New features

### Direct tool selection in search

The `mcp_search_tool_bm25` [meta-tool](/core-concepts/meta-tools) now supports a `select:<name>` syntax that bypasses the search index entirely. If your agent already knows exactly which tool it wants — for example from prior context — it can call `select:github_create_issue` to retrieve that tool's description instantly, skipping the BM25 ranking step.

### Required terms in search queries

Search queries now support a `+term` prefix to strictly filter results. Prefixing a word with `+` guarantees that only tools whose name or description contain that word are returned. For example, `+slack send` ensures only Slack tools are returned, even if other tools use the word "send" more frequently. This makes tool discovery noticeably more reliable when working across many MCP servers.

## Updates

### Smarter tool ranking heuristics

The BM25 index powering the [Tool Router](/core-concepts/tool-router) search strategy now applies stronger scoring bonuses when a query term matches a tool's server name or tool name directly. Searching for "neon" or "apify" now reliably surfaces tools from those integrations first, instead of unrelated tools that happen to mention the word in their parameter descriptions.

### `serverId`-based tool routing

Tool routing across adapters and meta-tools now uses a stable `serverId` instead of the human-readable server name. This prevents collisions when two servers share a similar name and makes routing behavior predictable across reconnects.

## Bug fixes

- **Exact-match search limits** — Fixed an issue where `topK` was not respected when the search index returned exact name matches, occasionally returning more results than requested.
- **Select path error reporting** — The `select:` path now correctly reports `isError=true` and surfaces the missing tool name when no matching tools can be resolved, making failures easier to handle in agent loops.
- **Required-term embedding queries** — Normalized query text used for embedding lookups so `+term` filters behave consistently across keyword and semantic search.
